# KevinOS 30-day local adoption soak

Start this scorecard on the first day v0.50 becomes Kevin's daily driver. It is local evidence for pruning and promotion—not external analytics and not a reason to add more rooms.

## Daily check (days 1–30)

Copy one row per day. Use `yes`, `no`, a duration, or a short friction note.

| Date | Opened | Capture visible under 10s | Focus confirmed under 2m | Close ritual | Proposal backlog | Recovery/data failure | Friction worth removing |
|---|---|---|---|---|---:|---|---|
| YYYY-MM-DD |  |  |  |  |  |  |  |

When a recovery, import, snapshot, sync, or convergence failure occurs, record the exact action and preserve the affected backup before changing anything.

## Weekly review (days 7, 14, 21, 30)

- Opened KevinOS at least 5 of 7 days.
- Capture was visible within 10 seconds.
- First focus was set or confirmed within two minutes.
- Close ritual completed at least three times.
- AI proposal backlog remained at three or fewer.
- Accepted, edited, rejected, escalated, and failed proposal patterns are visible in the local Proposal Inbox summary.
- Zero unresolved data-loss, import, snapshot, recovery, or convergence failures.
- Inspect local `roomStats`: demote rooms that add noise and preserve the rooms that earn repeat use.

## Day-30 decision

Record one of: `KEEP`, `DEMOTE`, `REMOVE`, or `RUN A SMALLER TEST` for each recurring friction point. Prefer removing or simplifying before adding another room, card, provider, or automation. Broad public/SaaS productization remains Track B and requires a separate decision after this personal-use soak.
